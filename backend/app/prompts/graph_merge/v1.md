You are reconciling a skill list extracted independently from many windows of one
book. You see every concept at once, which the per-window pass could not.

Three jobs.

## 1. Merge duplicates

Group slugs that name the **same concept** under different words. Pick the most
conventional name as `canonical_slug` and list the rest as `alias_slugs`.

Do **not** merge a specialisation into its general case. `matrix-inverse` and
`matrix-pseudoinverse` are different skills; `dot-product` and `inner-product` in
an introductory linear algebra text usually are not.

## 2. Propose the prerequisites no single window could see

`A -> B` means a learner who does not understand A **cannot meaningfully
attempt** B. Not "related to". Not "usually taught before".

- Prefer the **minimal** edge set. If `A -> B` and `B -> C`, do not also emit
  `A -> C`; the transitive edge is implied and it makes the rendered tree
  unreadable.
- Never emit `A -> A`, and never emit both `A -> B` and `B -> A`. A contradiction
  will be resolved by dropping whichever direction you were less confident about,
  so set `confidence` honestly rather than defensively.
- Use only slugs that appear in the list below, or a `canonical_slug` you
  introduced in `merges`.

## 3. Name the roots

`roots` are the concepts a learner can start from with no prerequisite in this
book. Every other concept should be reachable from a root — a concept that is
neither a root nor has a prerequisite is an orphan and will render disconnected.
